# UniversalExternalDataProcessors

Шаблон **универсальной регламентной обработки 1С** на Библиотеке стандартных подсистем (БСП):
внешняя обработка вида «Дополнительная обработка», которая подключается через справочник
`ДополнительныеОтчетыИОбработки` и запускается по расписанию.

Шаблон не привязан к прикладной конфигурации — нужна только БСП в базе.

## Что внутри

```
epf/ШаблонРегламентнойОбработки/src/   XML-исходники (формат 2.20, платформа 8.3.27)
scripts/epf-vm.sh, epf-vm.ps1         сборка и разбор .epf через ibcmd в Windows-VM
scripts/bsl-check.sh                   статический анализ BSL Language Server с метаданными БСП
scripts/form-check.py                  сверка модулей форм с их XML
```

Объектный модуль: описание для БСП, список команд, диспетчер выполнения, инициализация данных,
сбор результата и отправка прогресса. Форма строит кнопки из списка команд и запускает их фоновым
заданием: статус, индикатор прогресса, текущий шаг и кнопка отмены — прямо на форме, без модального
окна ожидания. Лог выполнения выгружается в файл.

## Как добавить свою команду

1. Строка в `ПолучитьСписокКоманд`:

```bsl
Результат.Добавить(Новый Структура("Идентификатор, Представление, Группа",
	"ОбновитьКурсы", "(2) Обновить курсы валют", "Основные"));
```

2. Одноимённая процедура в области `ПрограммныйИнтерфейс` — диспетчер вызовет её по имени:

```bsl
Процедура ОбновитьКурсы(ПараметрыВыполнения = Неопределено) Экспорт

	ВыходныеДанные.Успешные.Добавить("Курсы обновлены");

КонецПроцедуры
```

Карточка БСП и кнопки на форме подхватят команду сами.

Чтобы на форме был виден ход работы, сообщайте прогресс из процедуры команды:

```bsl
Для Номер = 1 По Всего Цикл
	СообщитьПрогрессКоманды(Номер - 1, Всего, СтрШаблон("Обработка %1 из %2", Номер, Всего));
	// ...
КонецЦикла;
```

Вне фонового задания (синхронный запуск, запуск по расписанию) вызов ничего не делает.

## Как это запускается по расписанию

Администратор загружает `.epf` в справочник `ДополнительныеОтчетыИОбработки` и настраивает
расписание в карточке. БСП создаёт регламентное задание по метаданным
`РегламентныеЗадания.ЗапускДополнительныхОбработок`; оно вызывает
`ДополнительныеОтчетыИОбработки.ВыполнитьОбработкуПоРегламентномуЗаданию`, а та доходит до
процедуры `ВыполнитьКоманду` в модуле объекта обработки.

**Расписание нельзя объявить в коде** — в таблице команд `СведенияОВнешнейОбработке` колонки
расписания нет. Кнопка «Настроить расписание» видна только для глобальных видов обработки
(`ДополнительнаяОбработка`, `ДополнительныйОтчет`).

## Сборка

```bash
scripts/bsl-check.sh epf/ШаблонРегламентнойОбработки/src
python3 scripts/form-check.py epf/ШаблонРегламентнойОбработки/src
scripts/epf-vm.sh build ШаблонРегламентнойОбработки
```

Сборка идёт через `ibcmd` 8.3.27 в Windows-VM по `ssh`; параметры подключения и учётка базы берутся
из `.v8-project.json` (файл локальный, в репозиторий не попадает). Без VM собрать можно вручную:

```
ibcmd config import --db-path=<база с БСП> --user=<пользователь> --out=<файл.epf> epf/ШаблонРегламентнойОбработки/src
```
Подробности среды и ограничений — в [CLAUDE.md](CLAUDE.md).

## Проверено

Платформа 8.3.27.2130, демо-конфигурация БСП **3.1.11.466**:

- BSL Language Server с метаданными БСП — ошибок нет
- модули форм сходятся с XML форм
- круговой тест сборка → разбор — исходники совпадают побайтово
- все вызываемые методы БСП лежат в `#Область ПрограммныйИнтерфейс` (стабильный API)

**Не проверено:** запуск в 1С:Предприятии. Статические проверки не ловят часть ошибок, которые
находит только компиляция платформой, — подробности в [CLAUDE.md](CLAUDE.md), раздел «Проверка».

В версии 21.09.26 здесь было написано, что `/CheckModules` не нашёл синтаксических ошибок. Этот ключ
для внешних обработок ничего не проверяет — то утверждение ничего не значило.
